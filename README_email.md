# Письма с подходящими вакансиями

Дополнение к работающему `job_tracker.py` и задаче `LatviaVacanciesMorning`.

При первом успешном запуске для каждого получателя отправляется **отдельное письмо со всей текущей подборкой**. Затем ему приходят только вакансии, которые ещё не отправлялись на его адрес. Если новых для рассылки вакансий нет, письма нет. Утреннее время остаётся прежним — в твоей настройке это 09:00 по времени компьютера.

В письме: должность, компания, зарплата, город, формат работы, даты наблюдения и срока, ссылка на CV.lv. Данные поступают из сохранённых объявлений CSP Latvia: открытость набора проверь по ссылке перед откликом.

## Оформление DATA HIGIENE на латышском

Тема и текст письма теперь на латышском языке. Оформление: тёмно-синяя шапка DATA HIGIENE, голубые акценты, карточки с зарплатой и кнопкой CV.lv, подпись Janušs Barila. В подпись автоматически подставляется текущий адрес отправителя из окна настроек. Названия должностей и компаний сохраняются на языке исходных объявлений.

Для обновления закрой окно настроек, распакуй все файлы этого архива **в существующую папку проекта** и разреши заменить файлы дополнения. Повторно устанавливать утреннюю задачу или вводить пароль не требуется. Фильтры, адреса, сохранённый пароль и история отправок остаются прежними.

Открой `DATA_HIGIENE_preview.html` двойным щелчком в проводнике: это образец дизайна с тремя вакансиями из предоставленной подборки на 01.09.2026. Открытие файла ничего не отправляет и не загружает вакансии заново. Число 3 и зарплата от 2400 € в образце — демонстрационные данные; настоящие письма используют текущие фильтры и фактическое количество вакансий.

Новое оформление применяется к следующим письмам. Старые письма в почтовом ящике не меняются. Кнопка «Обновить и отправить» запускает обычную проверку: если на этот адрес всё уже отправлено, повторного письма не будет. Не удаляй историю отправок ради просмотра дизайна.

Даты показаны в виде `01.09.2026`; время проверки и точные сроки указаны в UTC. Например, `07.09.2026, 23:59 UTC` сохраняет часовой пояс исходного срока, не сдвигая дату без пояснения. Зарплаты отображаются с разделением тысяч, например `3 000–4 500 € / mēn.`; налоговый статус зарплаты не добавляется, поскольку в используемых полях он не подтверждён.

Письмо содержит HTML и обычную текстовую версию, ссылки на источник и лицензию CC BY 4.0. Изображения и внешние шрифты для оформления не требуются. Используются таблицы и встроенные стили; поддержка CSS зависит от почтового клиента ([документация Gmail](https://developers.google.com/workspace/gmail/design/css)).

## Простое окно настроек

Распакуй все файлы этого архива в папку проекта рядом с `job_tracker.py`. При обновлении разреши заменить файлы дополнения.

Дважды щёлкни **`Email_Settings.cmd` в проводнике Windows**. Откроется окно «Письма о вакансиях». Клик по этому файлу внутри VS Code открывает его текст; для запуска из терминала папки проекта используй ` .\Email_Settings.cmd`.

1. **Откуда отправлять** — полный адрес твоего Inbox.lv или Gmail.
2. **Получатели — один или несколько адресов** — адреса для уведомлений. Их можно вводить через запятую, точку с запятой или каждый с новой строки. Галочка **«Только самому себе»** подставляет адрес отправителя. Чтобы добавить других получателей, сними галочку.
3. **Специальный пароль почты** — введи новый пароль, если меняешь его или отправителя. Если меняешь только получателя, сохранённый пароль можно оставить: поле будет пустым с пояснением.
4. **Проверить подключение** — проверяет вход в почту, без отправки письма. Проверка идёт в фоне и не сохраняет изменения.
5. **Сохранить** — сохраняет адреса и зашифрованный пароль. Изменения используются при следующем запуске рассылки; сохранение само по себе письмо не отправляет.
6. **Обновить и отправить** — сохраняет введённые настройки, запускает свежую проверку вакансий и отправляет каждому его новые объявления. Дождись результата внизу окна. Если новых для получателя нет, ему письмо не отправится.

Существующие настройки подхватываются автоматически. Окно не заменяет расписание, фильтры или историю отправок. Для удобства можно создать ярлык на `Email_Settings.cmd` на рабочем столе.

Если рассылка ещё не подключена к утренней задаче, выполни первоначальное подключение ниже. После этого адреса и пароль меняй в окне.

## Несколько получателей

Закрой окно настроек, замени файлы дополнения из нового архива и открой его снова. Старый адрес и сохранённый пароль будут подхвачены автоматически. Обновляй все файлы архива вместе; повторно устанавливать утреннюю задачу не требуется.

Сними галочку **«Только самому себе»** и заполни поле получателей, например:

```text
first@example.com
second@example.com
```

Это пример формата — укажи нужные тебе адреса. Затем нажми «Сохранить» или «Обновить и отправить».

Повторяющиеся адреса автоматически удаляются из списка. Каждое письмо адресовано одному получателю; список остальных в него не включается. Все получают вакансии по текущим фильтрам трекера, но уже отправленные объявления учитываются отдельно для каждого адреса.

Новый получатель получит текущую подборку. При его добавлении прежним получателям повторно тот же список не отправляется. Чтобы исключить адрес из рассылки, удали его из поля и сохрани настройки. Если позже вернуть тот же адрес, программа вспомнит, какие вакансии ему уже присылались.

Если почтовый сервер отклонил одного получателя, программа продолжит с остальными. При повторном запуске успешные отправки не дублируются. Общая ошибка входа в почту останавливает отправку до исправления пароля.

Для обычного Inbox.lv действуют ограничения 15 писем в час и 5 в минуту. Поэтому программа делает паузы не менее 13 секунд между письмами и ограничивает свои попытки числом 15 за час. При достижении лимита оставшиеся получатели откладываются до следующего запуска, когда лимит освободится. Можно снова нажать «Обновить и отправить» позже; по расписанию они также будут проверены при следующем запуске. В подсчёт сервера входят и письма из других приложений. [Официальные ограничения Inbox.lv](https://help.inbox.lv/settings-for-email-client-software-pop3-imap-smtp?language=ru).

В конце появится итог: сколько писем принято сервером, у скольких получателей нет новых вакансий, сколько ошибок и сколько получателей отложено. Детали по каждому адресу находятся в последнем `logs\email_*.log`.

## Первоначальное подключение

1. Распакуй **все файлы** из архива в папку:

   `C:\Users\FlyUp Travel\Desktop\Python Biznesa datu analze`

   Они должны лежать непосредственно рядом с твоими `job_tracker.py` и `job_filter_mcp.py`, а не во вложенной папке. Дополнение не содержит замен этих двух файлов. Настройки фильтров и база истории остаются твоими.

2. В терминале PowerShell выполни:

   ```powershell
   Set-Location "$env:USERPROFILE\Desktop\Python Biznesa datu analze"
   powershell -NoProfile -ExecutionPolicy Bypass -File .\install_email_notifications.ps1
   ```

   `ExecutionPolicy Bypass` применяется к этому запуску процесса; постоянная политика Windows не меняется. Установщик использует Python из уже работающей утренней задачи, поэтому команда `uv` в PATH ему не нужна.

3. Мастер задаст три вопроса:

   - **Адрес отправителя:** введи свой полный Inbox.lv email, который использовал для Python-отправки писем. Также поддерживается Gmail.
   - **Получатели:** один или несколько адресов через запятую или точку с запятой. При первой настройке по умолчанию используется адрес отправителя, при повторной — сохранённый список.
   - **Специальный пароль / пароль приложения:** введи его в терминале. Символы не отображаются — это нормально.

   Для Inbox.lv нужен доступ к внешним почтовым программам и специальный пароль из [настроек Inbox.lv](https://email.inbox.lv/prefs?group=enable_pop3). Используй уже выданный специальный пароль, если он у тебя сохранён. [Официальная инструкция](https://help.inbox.lv/settings-for-email-client-software-pop3-imap-smtp?language=ru).

   Для Gmail требуется пароль приложения из [настроек Google](https://myaccount.google.com/apppasswords); для создания нужна двухэтапная аутентификация. Возможность доступна не всем типам аккаунтов. [Инструкция Google](https://support.google.com/accounts/answer/185833?hl=ru).

   Пароль вводится только на твоём компьютере. Он сохраняется в зашифрованном виде средствами Windows для текущего пользователя, а не открытым текстом в программе. При настройке мастер проверяет вход на почтовый сервер и сохранение/расшифровку секрета.

4. После успешной настройки появится `EMAIL SCHEDULE READY`. Установщик подключит рассылку к существующей утренней задаче и сразу запустит свежую проверку. Если подходящие вакансии есть, она отправит первое письмо. После строки «Почтовый сервер принял письмо» проверь входящие и спам. Принятие сервером ещё не гарантирует попадание во входящие.

Компьютер, как и раньше, должен быть включён, подключён к интернету; нужно войти под тем же пользователем Windows. Можно заблокировать экран. Настройку не запускай от другого пользователя или от администратора вместо своего обычного аккаунта.

В папке проекта:

```powershell
& "$env:USERPROFILE\.local\bin\uv.exe" run .\job_tracker_email.py
```

Обычный запуск `job_tracker.py` обновляет таблицы. Для обновления **и отправки письма** используй новый `job_tracker_email.py`; утренняя задача после установки делает это сама. Сохранение фильтра само по себе письмо не запускает.

## Принудительно отправить одно тестовое письмо себе

После обновления файлов этого архива выполни в PowerShell:

```powershell
Set-Location "$env:USERPROFILE\Desktop\Python Biznesa datu analze"
& "$env:USERPROFILE\.local\bin\uv.exe" run .\job_tracker_email.py --test
if ($LASTEXITCODE -eq 0) { Invoke-Item .\email_test_preview.html }
```

Команда обновит вакансии через твой трекер и отправит **ровно одно письмо на адрес отправителя из настроек**, даже если эти объявления ему уже приходили. Другим адресатам тест не отправляется. Тема начинается с `[TESTS]`, а внутри письма есть отметка о проверке. Затем команда откроет HTML-копию в браузере. Принятие письма сервером ещё не гарантирует попадание во входящие: при необходимости проверь спам.

История обычных уведомлений не очищается и не дополняется тестовыми вакансиями. Сам факт тестовой отправки записывается отдельно в журнале партий, чтобы учитывать ограничение Inbox.lv. Повторный ручной запуск `--test` создаёт ещё одно тестовое письмо; по утреннему расписанию тесты не отправляются. Если свежая подборка пуста, придёт тест без карточек с пояснением. Истёкшие объявления исключаются; при ошибке обновления письмо не отправляется.

Если результат передачи оказался неизвестен, проверь почту до следующего ручного теста. Автоматического повтора тестового письма нет. Статус показывает тестовые письма отдельно от обычных.

Для обновления и просмотра **без отправки**:

```powershell
& "$env:USERPROFILE\.local\bin\uv.exe" run .\job_tracker_email.py --preview
if ($LASTEXITCODE -eq 0) { Invoke-Item .\email_test_preview.html }
```

Этот режим создаёт актуальный `email_test_preview.html`, не подключается к почте и не читает сохранённый пароль. Для обновления данных нужен интернет. HTML-файл может открываться и без интернета после создания; наличие копии не подтверждает доставку письма.

## Что считается новым для рассылки

Идентификатор вакансии учитывается отдельно для каждого адреса получателя. После подтверждённого принятия письма сервером та же вакансия повторно не отправляется — даже при повторном запуске, изменении зарплаты или временном исчезновении из фильтра. При смене получателя его первая подборка может содержать уже знакомые вакансии.

Это отдельный учёт от `vacancies_new.csv`: CSV показывает впервые найденные трекером за день, рассылка — ещё не отправленные объявления из свежей текущей подборки. До отправки повторно проверяется срок. Уже не подходящие текущему фильтру или истёкшие объявления в повторную попытку не включаются.

Если обновление данных завершилось ошибкой, старый список не рассылается. Если SMTP явно отказал или подключение не удалось до передачи письма, следующая проверка попробует отправить ещё не отправленные актуальные вакансии. Если ответ сервера потерялся во время передачи, автоматического повтора этого письма не будет до ручной проверки: иначе возможен дубль.

## Если письмо не пришло

Посмотри последний `logs\email_*.log`; подробности проверки вакансий — в `logs\run_*.log`. Проверь папку «Спам» и правильность адреса. Нет новых для рассылки вакансий — ожидаемо нет письма.

Статус отправок:

```powershell
& "$env:USERPROFILE\.local\bin\uv.exe" run .\vacancies_email.py --status
```

Если журнал сообщает «неподтверждённая отправка», сначала проверь почту, затем:

```powershell
& "$env:USERPROFILE\.local\bin\uv.exe" run .\vacancies_email.py --resolve
```

Выбери «получил», чтобы учесть письмо, или «не получил», чтобы разрешить повтор актуальных вакансий при следующем обновлении. Ручной повтор может дать дубль, если первое письмо всё-таки было доставлено с задержкой.

Для замены адреса или специального пароля открой **`Email_Settings.cmd`**, внеси изменения и нажми «Сохранить».

Если работаешь через старый мастер в PowerShell, сначала запусти команду `vacancies_email.py --setup` и дождись строки «Специальный пароль». Пароль вводится только в ответ на этот запрос. Строка `PS C:\...>` ждёт команду, а не пароль. Символы пароля при вводе в терминале не отображаются.

## Служебные файлы

- `vacancies_email_config.json`: адреса, настройки SMTP, зашифрованный секрет. Не пересылай его для диагностики; на новом компьютере повтори настройку.
- `vacancies_email.sqlite3`: учёт отправленных вакансий. Не удаляй, чтобы старые объявления не отправились снова.
- `vacancies_email.lock`: защита от одновременных запусков рассылки.
- `email_preview.html`: вид последнего подготовленного письма.
- `email_test_preview.html`: вид последнего подготовленного теста или предпросмотра.
- `email_archive\*.eml`: копии подготовленных писем; наличие файла само по себе не означает успешную отправку.
- `logs\email_*.log`: результаты запусков рассылки.

Python использует только стандартную библиотеку. Почтовое дополнение совместимо с версией 1 базы истории текущего трекера. Оно читает эту базу, а свой учёт ведёт отдельно. Установщик меняет только действие существующей задачи, сохраняя расписание и условия запуска.

Окно сохраняет почтовую конфигурацию версии 2 со списком получателей. Старая конфигурация версии 1 читается автоматически; история отправок и пароль сохраняются при обновлении.

## Проверка этой версии

В среде разработки прошли 12 проверок: первая подборка, повторы на следующий день, новые ID, сроки, смена фильтра/исчезновение, разные получатели, ошибки входа и явные отказы SMTP, неопределённая отправка/авария процесса и ручное разрешение, блокировка параллельных запусков, совместимость с существующей историей, свежесть запуска, TLS и ошибка при закрытии уже успешного соединения.

Реальные вход в почту, доставка и изменение задачи Windows проверяются на твоём компьютере установщиком. Из среды разработки письма не отправлялись; Windows здесь недоступна.

Окно настроек использует встроенный модуль Python Tkinter. Сохранение адресов работает без интернет-подключения, проверка входа требует интернета. После переноса на другой компьютер введи специальный пароль заново.

Для окна дополнительно проверены 7 сценариев: сохранение нового получателя с прежним паролем, смена отправителя, замена секрета, одновременное редактирование, неверные адреса/занятая рассылка, проверка входа без отправки, запуск существующего трекера кнопкой. Эти проверки выполнены с тестовыми данными и имитацией почтового подключения; настоящий пароль не использовался. Запуск графического окна в Windows в этой среде не проверялся.

Для нескольких получателей добавлены ещё 9 проверок: разделители/дубли/ошибки адресов, переход со старой конфигурации, отдельные письма, отказ одного получателя и независимый повтор, неопределённая доставка, общая ошибка входа, часовой лимит, паузы и повтор без новых вакансий, новые объявления и исключение адреса.
